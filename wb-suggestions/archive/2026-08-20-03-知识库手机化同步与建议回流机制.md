# 知识库手机化：ima 自动同步 + 建议自动回流 机制

## 背景

用户希望本地知识库（`C:\1xiangmu\yixiao`，一消备考）能在 Android 手机上使用，约束：
- 不依赖电脑开机
- 手机端只做问答 + 保存修改建议（不改知识库）
- 遵守 AGENTS.md：opencode 唯一写入方，问答 agent 只读 + 建议回流

经 WorkBuddy 调研确定方案：**ima 知识库存"知识依据"+ 手机端用 WorkBuddy App 云端模式连 ima 做问答**（不直接用 ima App）。

ima 关键能力：
- 支持导入 Markdown + PC 端上传文件夹（保留层级结构）
- 有官方 OpenAPI（https://ima.qq.com/agent-interface 取 Client ID + API Key；端点 `https://ima.qq.com/openapi/wiki/v1/`，认证 Header `ima-openapi-clientid` + `ima-openapi-apikey`）
- ima 笔记可通过 API 读取（`ima-go note list` / `note cat` / `note export`）

知识库现状：以 .md 为主（1266 个，67%）。核心 `knowledge-base/` 约 40 条目，frontmatter 已含讲义页码引用（`sources.section` 如 `P177-179`）与规范条文（`regulation_refs`），**故不上传 PDF 也能在问答中引用页码**。`materials/` 有 1.7G PDF。

## 重要：题眼/习题/真题 PDF 不得入 ima 知识库（防混淆）

用户实测发现：若把题眼（题目/题干）PDF 与知识 .md 混在同一个 ima 知识库，ima 检索时不分"题目"与"依据"，会把题目内容当依据引用。

**结论**：ima 知识库**只放知识依据**（.md），**题眼/习题/真题 PDF 一律不入库**；题目作为每次问答的**对话输入**贴给 WorkBuddy，由 WorkBuddy 明确"题目是要答的对象、知识库是依据"。

具体排除（不同步、不上传）：
- `materials/exercises/`（2/4/6 号书习题 PDF，题眼）
- `materials/past-exams/`（2015-2023 真题 PDF，题眼）
- `materials/` 根目录模拟题 PDF（如 `2026moni shiwu_1.pdf`、`ctb_*.pdf`，题眼）
- `materials/lectures/`、`materials/mind-maps/`（讲义/导图 PDF，体积大，手机不查原文）

## 建议 opencode 落实的两件事

### 建议一：opencode 实现知识库 → ima 自动同步

**目标**：opencode 每次完成知识库写入（git commit）后，自动把变更的 .md 同步到 ima 知识库，使手机端 ima 问答始终基于最新版本。

**实现要点**：
1. **取凭证**：访问 https://ima.qq.com/agent-interface 生成 Client ID + API Key，存入项目配置（如 `.opencode/ima-sync.config`），并加入 `.gitignore`，不入库。
2. **同步方式**（二选一，推荐 A）：
   - **A. ima-go CLI**（省事）：`go install github.com/xavierli330/ima-go@latest`，用 `ima-go sync C:\1xiangmu\yixiao\knowledge-base\`（SHA-256 增量，只传新/改文件）；可配合 `ima-go kb watch` 监听自动上传。
   - **B. 自写脚本调 ima OpenAPI**：`create_media` 取 COS 凭证 → 官方 `cos-upload.cjs` 传腾讯云 COS → `add_knowledge` 入库（Markdown `media_type=7`）。
3. **同步范围（仅知识依据，排除题眼）**：只同步 `knowledge-base/`（核心）、`errors/`、`materials/qimen-dunjia/`（口诀 .md）。题眼/习题/真题 PDF、讲义/导图 PDF、`tools/` 脚本一律不同步（详见上文"重要"小节，防止题眼混入依据库）。
4. **触发**：opencode 在 git commit 后自动运行同步；失败时输出告警，不阻断 commit。
5. **首次导入**：先在 ima PC 端新建个人知识库「一消备考知识库」，首次全量上传上述三个文件夹（PC 端「上传文件夹」保留层级），之后用同步脚本增量维护。

### 手机端问答入口与约定（WorkBuddy App 云端模式连 ima）

**入口**：手机端用 WorkBuddy App，切到「☁️ 云端工作」模式，连接 ima「一消备考知识库」（仅知识依据）作为检索源。**不直接用 ima App 问答**。

**问答约定**（用户每次在 WorkBuddy 对话里这样组织）：
1. **题目作对话输入**：把要答的题（题眼）贴进对话，明确"这是一道题，请作答"
2. **依据来自知识库**：要求 WorkBuddy 基于已连接的 ima 知识库内容作答，引用讲义页码（.md frontmatter 的 `sources.section`）与规范条文（`regulation_refs`）
3. **角色分明**：题目=要答对象，知识库=依据，不得把题目当依据引用

**模型/成本提示**：WorkBuddy 云端模式走 WorkBuddy 模型（消耗其额度），与 ima App 直答（免费 DeepSeek R1 不限次）不同。换 WorkBuddy 是为获得更灵活的对话控制（明确题目/依据角色分工），代价是额度消耗——用户已知悉并接受。

### 建议二：opencode 实现 ima 建议笔记 → wb-suggestions/pending/ 自动回流

**目标**：用户在手机 WorkBuddy App 问答时，把修改建议存为 ima 笔记（[建议] 标记）；opencode 回电脑后自动拉取这些笔记，转成本地 `wb-suggestions/pending/` 建议文件，再按 `wb-suggestion-processing.md` 核对写入。

> 若 WorkBuddy App 无法直接往 ima 存笔记，退而求其次：建议存为 WorkBuddy 资料库在线文档，回电脑后由用户手动粘贴到 ima 笔记；或由 WorkBuddy 桌面会话从资料库读取后转写到 `wb-suggestions/pending/`（该目录是 WorkBuddy 唯一可写区）。

**实现要点**：
1. **约定标记**：用户在 ima 存建议笔记时，标题前缀 `[建议]` 或打标签 `wb-suggestion`，便于 opencode 精确拉取，避免误读普通笔记。
2. **拉取**：opencode 调 ima API（`ima-go note list --format json` / `ima-go note cat <id>`）读取带标记的新笔记。
3. **转写**：对每条建议笔记，在 `wb-suggestions/pending/` 新建文件，命名 `YYYY-MM-DD-序号-主题.md`，内容按 `templates/blindspot-suggestion.md` frontmatter 转写（date/source_qa/suggest_type/status=pending），正文保留用户建议原文。
4. **登记台账**：登记到 `wb-suggestions/待处理清单.md`，来源标记「ima 笔记回流」。
5. **去重**：拉取后给 ima 端该笔记加标记或移入子文件夹（如 `已回流/`），避免重复拉取。
6. **后续**：按既有 `wb-suggestion-processing.md` 流程——逐条回查讲义/规范原文（全量检验）→ 接受写入 `knowledge-base/` 并更新 `index.md`，或归档 `archive/`。

## 合规边界（必须遵守）

- **opencode 唯一写入方**：本地 `knowledge-base/`、`errors/`、`index.md`、`wb-suggestions/pending/` 的写入均由 opencode 完成；手机端/ima 端只产生建议笔记，不直接写本地。
- **git 白名单**：同步与回流脚本只允许在 `wb-suggestions/pending/**` 产生新建议文件，或操作 ima 云端；不得改动 `knowledge-base/` 等只读位置（除非走正式写入流程并全量检验）。
- **凭证安全**：ima API Key 存配置文件并加入 `.gitignore`，不入库、不写进知识库、不进产物。
- **不破坏现有工作流**：同步/回流作为 opencode 既有「写入维护」职责的延伸，与补录/校验/错题录入流程并行，不替代。

## 验证标准

- 知识库变更后，ima 中对应 .md 更新（手机问答能查到最新内容）。
- 手机 WorkBuddy 问答后存一条 `[建议]` 笔记到 ima，opencode 回电脑拉取后，`wb-suggestions/pending/` 出现对应建议文件并登记台账。
- 题眼 PDF 未出现在 ima 知识库中（验证：ima 知识库内搜不到题干原文作为依据被引用）。
- 全程不违反 AGENTS.md 角色边界。
